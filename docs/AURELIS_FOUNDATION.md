# AURELIS Foundation

**AURELIS** — Adaptive Unified Reasoning, Evidence, Research, Intelligence & Strategic Execution System.

## Project identity

AURELIS is the new primary system identity. OSIRIS is retained as the first-generation intelligence/OSINT subsystem and historical implementation lineage.

The existing `KingRwaz/osiris` repository is a fork of `simplifaisoul/osiris`. It is therefore treated as an experimental/reference source, not as the proprietary foundation of AURELIS.

## Integration principle

AURELIS will absorb useful OSIRIS capabilities through explicit subsystem boundaries rather than treating the fork as the project's permanent identity.

### OSIRIS subsystem

- Global situational-awareness visualization
- Geospatial intelligence layers
- Aviation, maritime, seismic, fire, weather and space feeds
- News aggregation and live broadcast presentation
- OSINT/reconnaissance interfaces
- Vulnerability/CVE intelligence presentation

### AURELIS system layers

1. **Evidence ingestion** — external feeds, documents, APIs and operator-provided material.
2. **Normalization** — common schemas, provenance, timestamps and confidence metadata.
3. **Knowledge layer** — searchable documents, entities, relationships and persistent memory.
4. **Reasoning layer** — retrieval, synthesis, verification and multi-agent analysis.
5. **Intelligence layer** — OSIRIS capabilities plus additional analytical domains.
6. **Strategic execution** — decisions, plans, workflows, tasks and auditable actions.
7. **Presentation layer** — dashboards, maps, reports, diagrams and operator workspaces.
8. **Governance** — authentication, authorization, secrets management, audit trails and safety controls.

## Repository transition

The current branch `aurelis-foundation` is a staging branch for migration and restructuring. The public `master` branch remains unchanged.

The intended destination is a new **private** repository owned by `KingRwaz`, with AURELIS as the repository identity and OSIRIS preserved inside the architecture as a subsystem.

Until repository-creation permissions are available through the connected GitHub tooling, no claim is made that the private destination repository has been created.

## Non-negotiable provenance rule

Every imported component must retain its upstream provenance and license information. Fork-derived code must not be represented as original AURELIS code merely because it has been integrated or renamed.
